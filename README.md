# 错题手帖

拍照识题 → 自动整理成可复习的错题本。PWA 与 Android APK 双端，数据云端同步。

**[在线体验](https://cuotiji-58055.app.workbuddy.host/)** · 原生 JavaScript · PWA · [MIT](LICENSE)

真实使用记录：1 名高三学生（数学／英语）+ 1 名初中学生（物理／数学），连续 12 天，入库 50 道错题，复习 24 次。

## 结构

```
index.html        单页外壳
app.js            全部逻辑（约 210KB，无框架、无构建）
styles.css
sw.js             Service Worker：离线可用、缓存策略
manifest.json     PWA 清单
vendor/           云服务客户端 SDK
```

没有打包步骤。改完 `app.js` 刷新页面就生效，部署就是拷目录。

## 三个真实故障，以及各自的根因

这些不是假设的边界情况，是线上被抓到的。

**1. 模型「先交卷再做题」。** 返回的 JSON 里 `answer` 排在 `analysis` 前面，模型于是先给答案再倒推过程，导致同一道三问立体几何只答对两问。把字段顺序改成 `analysis` 在前，同一道题三问全对。**输出结构的顺序会改变模型的行为**，这条比提示词怎么写更要紧。

**2. 识题 38 秒硬超时掐断长推理。** 带图的长推理经常超过 38 秒，请求被掐断后前端只能报错。改为 `120000` 毫秒，并在等待期间分阶段提示（识别 → 读取 → 生成），让用户知道没卡死。

**3. 选择题选项被吞。** 模型有时只返回题干和答案字母，不返回 A/B/C/D 选项，学生看到「答案是 C」但不知道 C 是什么。三层兜底：提示词里强制要求原样保留选项 → 返回后代码校验选项数组是否完整 → 不完整则带错误信息自动重试一次。

## 图像处理的几处细节

- **扫描保色**：批注常用红笔，普通灰度或自动白平衡会把红色洗掉。三通道用同一倍率映射，避免偏色，红笔仍然读得出是红的。
- **画布清晰度**：canvas 按 `devicePixelRatio` 重设尺寸再缩放绘制，解决高分屏下的模糊。
- **大图**：用 `createImageBitmap` 解码，避免主线程卡住。
